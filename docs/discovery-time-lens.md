# 发现史时间轴探索

这是一份蓝天探索笔记，不改变当前可浏览原型的评审目标。当前唯一前端 review target 仍应是能稳定启动、读取正式 `data/species-seed.json`、并通过桌面/移动浏览器测试的 3D 蝴蝶地球仪。

## What If

如果下一轮要把 demo 从“地球上有 10 个点”推进到“我看见一段自然史知识如何形成”，可以给地球仪加一个发现史时间轴。

时间轴不是普通年份筛选器，而是一个叙事镜头：

1. 拖动年份滑杆，marker 按首次正式描述年份逐步显影。
2. 同一时间段内，卡片优先显示命名者、原始描述来源、type locality 或 original description locality。
3. 坐标可信度随 marker 一起可视化：精确点、区域圈、低精度光晕在时间轴上同时出现。
4. 用户点开一个物种时，可以看到“地点声明来自哪里、图片授权来自哪里、这个点为什么只能画到这个精度”。

这样 demo 的记忆点会从“能点击图片卡片”变成“我能看见一个物种如何进入人类的知识系统”。

## 为什么适合这个产品

- 蝴蝶本身有视觉吸引力，但“发现史”才是这个地球仪和普通物种图鉴的差异。
- 当前 seed 已经有年份、命名者、地点口径、source URL、license 和坐标精度，足够支撑最小版本。
- 时间轴会自然暴露数据不确定性，避免把 `curated surrogate` 或低精度区域点包装成精确发现地。
- 60-90 秒 demo path 更容易讲：全球概览 -> 年份推进 -> 对比 2-3 个发现地点 -> 打开博物馆标本标签式卡片。

## 最小交互

- 顶部或底部放一个年份滑杆，默认范围来自正式 seed 的最早和最晚 `discoveryYear` 或命名年份。
- 滑杆左侧显示当前年份，右侧显示当前可见物种数量。
- marker 在年份到达后淡入；低精度记录仍使用大范围 halo，不因为时间轴动画变成精确 pin。
- 卡片增加一行“entered record”：用命名年份、命名者和地点口径解释为什么它在这个年份出现。

## 需要补齐的数据字段

最小版本可以先复用现有字段，但如果要做成稳定功能，后续 seed 应明确区分：

- `describedYear`: 物种被正式描述或命名的年份。
- `describedBy`: 命名者或原始描述作者。
- `recordBasis`: `type locality`、`original description locality`、`curated surrogate` 等。
- `recordSourceUrl`: 支撑年份和地点口径的来源。
- `coordinatePrecisionKm`: 时间轴上仍必须参与视觉降级。

如果这些字段在当前 seed 中已经以其他名称存在，先在 view model 做映射，不要为了 UI 直接改 schema。

## 不建议现在做的事

- 不要扩物种数量来制造时间轴密度。10 条正式 seed 足够验证交互。
- 不要把殖民采集路线或博物馆网络做成首版硬需求；这需要更多来源和解释成本。
- 不要在数据不足时展示连续年代热力图。年份稀疏应该如实呈现。

## 可评审的下一步

在当前原型稳定后，单独开一个时间轴 spike：

1. 只读正式 `data/species-seed.json`。
2. 不改 schema，先在 `src/species-view-model.mjs` 派生年份与卡片文案。
3. 增加一个 Playwright 检查：拖动或设置年份后，marker 数量按年份变化，点击卡片仍能看到 provenance、license 和坐标可信度。
4. 截图覆盖桌面和窄屏，确认滑杆、卡片和地球不会互相遮挡。

如果 spike 不能在 10 条 seed 上讲清楚故事，问题大概率是数据叙事或卡片层级，而不是物种数量。
